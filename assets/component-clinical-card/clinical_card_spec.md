# 组件：临床 / 药物介绍卡（胶囊风格）

紫色系组件集，用于公众号文章里**一段一个药物 / 一项临床研究**的介绍。
目录 `assets/component-clinical-card/`，可填空骨架在 `clinical_card_template.html`，
成品对照在 `clinical_card_specimen.html`。

**路由关键词**：临床介绍 / 药物介绍 / 药物卡片 / 临床卡片 / 试验卡片 / 在招研究 /
新药速览 / 分子盘点 / 靶点药物对比 / 入组路径 / 找谁看 / 中心速查。
看到这类请求，先来执行流程（下面第 1 条），而不是从零设计版式。

---

## 1. 与「长篇临床情报报告里的药物卡」的区别

情报报告（NCT/状态/申办方 表格 + 四块药物卡）要求的是**完整画像**：
药物属性 / 治疗原理 / 研发阶段 / 历史已发布数据，四块顺序固定。
这套胶囊组件是**公众号读者视角的紧凑版**，一次只讲一件事，视觉上要能快速扫读：

| | 长篇情报报告药物卡 | 本组件（胶囊卡） |
|---|---|---|
| 场景 | 内部情报、研究周报 | 公众号文章正文中给患者看 |
| 篇幅 | 一药一大块，四块齐全 | 一药一张卡，7～9 行够 |
| 优先级 | 完整、可溯源 | 能扫、能判断「跟我有关系吗」 |
| 数据粒度 | 列出全部已公布终点 | 只留主线，小样本信号必须标注 |

**两者都守同一批红线**（第 4 条）。区别只在密度，不在严谨度。

---

## 2. 三张卡的组合

一篇「药物 / 在招研究」章节的典型结构是：

```
① 标准卡 ×N（每个药物或研究一张，按重要度排）
② 迷你卡 ×M（中心速查：哪些医院能去、找谁）
③ 灰底解释框 ×1（数据口径 / 为什么某中心还没开筛）
```

顺序固定为 **先标准卡、后迷你卡**——先讲清分子，再讲去哪看。
迷你卡只放「研究 / 联系 / 地址（或提示）」三行，正文 12.5px，一屏能放七八家中心。

## 3. 结构与色板

### 占位符速查（19 个）

| 占位符 | 填什么 | 写在 |
|---|---|---|
| `__CARD_TITLE__` | 卡主标题：药物代号 / 研究简称 | 标准卡 |
| `__CARD_SUBTITLE__` | 副标：申办方 · 剂型 · 代次 | 标准卡 |
| `__CAPSULE_RECRUITING__` | 进展胶囊（薄荷色） | 标准卡胶囊行 |
| `__CAPSULE_NEUTRAL__` | 中性胶囊（灰紫） | 标准卡胶囊行 |
| `__CAPSULE_WARN__` | 注意胶囊（橙色） | 标准卡胶囊行 |
| `__INDICATION__` | 瘤种 / 适用人群 | 标准卡行组 1（带分隔线） |
| `__TRIAL__` | 试验编号：CTR / NCT / GCP | 行组 2 |
| `__PHASE__` | 分期、例数、关键日期 | 行组 3 |
| `__CENTERS__` | 中心与 PI | 行组 4 |
| `__DOSAGE__` | 剂型与给药 / 剂量 | 行组 5 |
| `__MECHANISM__` | 靶点与机制（没 disclosure 写「未披露」） | 行组 6 |
| `__DATA__` | 已公布终点（分注册节点与临床结果） | 行组 7（末行） |
| `__CARD_FOOTNOTE__` | 上市状态 / 数据口径限定 | 标准卡脚注 |
| `__MINI_TITLE__` | 中心名 + 研究名 | 迷你卡标题 |
| `__MINI_BADGE__` | 状态胶囊：「两项在招」「待启动」「非官方」 | 迷你卡标题行 |
| `__MINI_TRIAL__` | 这项研究是什么、收什么人 | 迷你卡行组 1 |
| `__MINI_CONTACT__` | 联系人（姓 + 医院）+ 官方公示的号码 | 迷你卡行组 2 |
| `__NOTE_TITLE__` | 灰底框小标题 | 灰底解释框 |
| `__NOTE_TEXT__` | 解释正文 | 灰底解释框 |

标签是写死的（瘤种 / 试验 / 分期 / 中心 / 剂量 / 机制 / 数据 / 研究 / 联系），
**每次只换右侧文字**——标签本身变来变去反而读不出扫读顺序。

### 标准卡

```
┌ 白卡  border-radius:16px  padding:20px 18px  box-shadow:0 4px 15px rgba(92,74,122,0.06)
│ ┌ 标题 16px #403358 粗体            __CARD_TITLE__
│ ├ 副标 11px #8d8a99                __CARD_SUBTITLE__（申办方 · 剂型 · 代次）
│ ├ 胶囊行 display:flex wrap          __CAPSULE_*__ ×3
│ ├ 行组 ×7  左标签列 + 右正文        __INDICATION__ / __TRIAL__ / __PHASE__ /
│ │                                   __CENTERS__ / __DOSAGE__ / __MECHANISM__ / __DATA__
│ └ 脚注 11px #8d8a99                __CARD_FOOTNOTE__
```

**行序（按患者阅读顺序，别打乱）**：瘤种 → 试验 → 分期 → 中心 → 剂量 → 机制 → 数据。

**胶囊取色（三选一，别四色混用）**：

| 语义 | 底 / 字 | 典型内容 |
|---|---|---|
| 进展 / 招募中 | `rgba(41,157,140,0.12)` / `#1f7a6b` | III 期在招、I 期在招、已有 Ib/II 人体数据 |
| 中性 | `rgba(92,74,122,0.08)` / `#6c6479` | 尚未招募、待启动、限 G12D、非官方 |
| 注意 | `rgba(232,116,73,0.10)` / `#9c4221` | 无人体数据、尚未获批、仅某突变 |

### 行组（最重要的复用单元）

```html
<section style="display:flex;align-items:flex-start;margin:0 0 8px;">
  <p style="flex:0 0 46px;margin:0;padding-top:1px;">
    <span style="display:inline-block;font-size:11px;line-height:1.7;padding:2px 8px;
                border-radius:20px;white-space:nowrap;background:rgba(92,74,122,0.08);color:#5c4a7a;">标签</span>
  </p>
  <p style="flex:1 1 0%;min-width:0;margin:0;color:#443a51;line-height:1.85;font-size:13px;">正文</p>
</section>
```

- **标签换词不换结构**：剂型 / 队列 / 节点 / 安全 / 同门 / 申办 / 登记 / 条件 / 排除 /
  A 组 / B 组 / C 组 / 地址 / 提示 / 提醒 / 联系 / 研究，都是同一个 `<span>` 里换两个/三个字。
- **加行**：复制整对 section，最后一个行组把 `margin:0 0 8px` 改成 `margin:0 0 0`。
- **只有第一行组带** `border-top:1px solid #efecf4;padding-top:11px`（和胶囊行分隔），其余不带。

### 两条 flex 硬约束（375px 实测，别凭感觉改）

| 标签字数 | 左列默认（`min-width:auto`） | 左列加了 `min-width:0` |
|---|---|---|
| 2 字（瘤种、数据） | 列 46px，胶囊 38px，正文列 329px ✓ | 完全一样 ✓ |
| 3 字（研究、联系） | 列 46px，胶囊 38px，正文列 329px ✓ | 完全一样 ✓ |
| 4 字（既往治疗） | 列被撑到 60px，正文列 315px，**不折行但挤窄正文** | 胶囊越出列 14px，**压到正文上** ✗ |
| 5 字（既往治疗线数） | 列被撑到 82px，正文列 293px ⚠ | 越出列 36px ✗✗ |

1. **标签一律 2～3 字**。这是整套组件最硬的约束：胶囊 `<span>` 带 `white-space:nowrap`
   不会自动折行，长标签只有两条出路——挤窄正文列（默认 auto 的行为）或者压到正文上
   （加了 `min-width:0` 的行为），两条都是坏结果。写标签时宁可换说法：
   「既往治疗线数」→「线数」，「中心数量」→「中心」。
2. **左列** `flex:0 0 46px` **不要加 `min-width:0`**。加了之后长标签不再把列撑开，
   而是直接溢出压到右侧正文（nowrap 不折行，视觉上是两列文字叠在一起）。
   2～3 字标签加不加都一样，但**养成不加的习惯**，换了个 4 字标签时才不会翻车。
3. **右列必须留 `min-width:0`**。登记号是一长串英文字母数字（一个 `NCT07142980` 后面
   还跟着三个号），没有它 flex item 会按内容宽度把整张卡撑破，375px 屏上直接横向滚动。

### 迷你卡 / 灰底框

- 迷你卡：白卡 `border-radius:14px padding:15px 16px`，标题行用 flex 两端对齐
  （左标题 `flex:1 1 0%`，右胶囊 `margin:0 0 0 8px`）；正文 12.5px。
- 灰底框：`background:rgba(92,74,122,0.06)`，比白卡低一级视觉权重，
  用来放「为什么还没开筛」「这个数字不能这么读」这类解释——
  它天然承认「不是结论」，比塞进标准卡更诚实。

## 4. 内容红线（三种卡通用）

沿用 `skill.md` 的「用户提供的药物资料三查」，胶囊卡因为密度高，**更容易把没依据的话写顺手**：

1. **机制没写就写「未披露」**，不推断。登记资料只写「RAS 突变或扩增」这类泛化描述时，
   不能反推出靶点。招募文案里的机制描述一律不能当依据（常见硬伤：改错适应症、张冠李戴到别的公司）。
2. **分清楚「注册节点」和「临床结果」**。IND 受理 / 获批临床 / 首例入组 / 剂量爬坡完成
   都只是进度，不是疗效进展；动物数据是临床前，必须标明。
3. **同靶点不同分子不能互相套数据**。一代静脉脂质体和下一代口服剂型，
   哪怕都在讲 G12D，数据也不能互相引用；这一条要在卡里明写（见样张 HRS-6093 的「同门」行）。
4. **小样本信号要标样本量**。「4 例胰腺癌 ORR 75%」不能变成「胰腺癌有效率高」——
   要么写样本量，要么明确写「属于继续开展 II 期的信号，不是已确立的疗效」。
5. **单臂数据不与随机 III 期比大小**，脚注里点一句即可。
6. **未披露 / 无公开数据 ≠ 没用**，写成「目前无公开人体疗效数据」比含糊带过诚实。
7. **公司名先核代号前缀再写主体**。HRS-xxxx 是恒瑞（江苏恒瑞医药），
   GFH-xxxx / GFS-xxxx 是劲方（GenFleet Therapeutics，2595.HK）——写错主体是硬伤。
8. **卡内只写「研究团队联系人：姓 + 医院」**，手机号留在官方原文或迷你卡里
   （迷你卡按官方招募公示填，填了就同步删旧号，别留可能换人的过期号码）。

## 5. 生成后检查清单

- [ ] 每个行组的标签都是 2～3 字，没有 4 字以上（4 字会把右列挤到只剩一行字宽）
- [ ] 右侧正文最长的那行在 375px 屏下没有横向溢出（`verify-layout.py` 会查）
- [ ] 胶囊不超过 3 个、不超过 3 种语义色
- [ ] 机制标了「未披露」，没有凭空推断
- [ ] 「数据」行区分了注册节点与临床结果；小样本写明了例数
- [ ] 同靶点不同分子之间写了「不可套用」
- [ ] 卡内脚注讲了数据口径（单臂 / 剂量探索 / 突破性治疗不是上市批准）
- [ ] 跑 `python3 scripts/verify-article.py <文章> --foot <foot 母版>`（组件只是片段的一部分，最终仍要过整篇九项）

## 6. 从零开始的一次执行顺序

1. 定章节要讲几个对象 → 每个对象一张标准卡；超过 5 个对象就先做迷你卡收口。
2. 每个卡先填 `__INDICATION__` 与 `__PHASE__`（患者最关心的两件事），再补试验号与中心。
3. 机制与数据两行**回查一手源**：登记平台 / 公司公告 / 会议摘要 / 已发表论文。
   查不到就照第 4 条写「未披露 / 无公开数据」，不要留空。
4. 迷你卡按中心整理，核一遍医院官网的科室与研究门诊信息（第三方平台滞后）。
5. 需要解释的地方用灰底框，不硬塞进标准卡。
6. 复制骨架 → 填占位符 → 跑 `scripts/check-placeholders.py assets/component-clinical-card`
   确认占位符与本文档一致 → 拼进文章 → 跑整篇九项校验 → 渲染长图自查溢出。
