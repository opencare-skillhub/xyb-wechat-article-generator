# template8-alliance 填写规范（医患联合群 / 科室共建招募文）

> 主模板：`alliance_template_purple.html`（紫色）
> 完整案例：`output/山西白求恩消化肿瘤科_联合群_公众号_purple.html`（2026-10）
> 章节骨架与硬规则：见 `skill.md`「医患联合群 / 科室共建招募文」一节（**先读那一节再动手**）

## 1. 触发

用户表达属于以下任一类时，用本模版：

- 「XX医院XX科和小胰宝建一个联合群」「共建病友群」「合作群」
- 面向某省/某地区招募患者入群
- 「不用跑外地」「在家门口治疗」「本地就能做」
- 某科室主任牵头的患者服务合作

版式固定为**紫色**（`review_template_purple.html` 体系的色值）。用户明确要求其他配色时替换色值，结构不动。

## 2. 占位符清单

| 占位符 | 含义 | 要求 |
|---|---|---|
| `__BRAND_LINE__` | 品牌行 | `小胰宝 · {省份}联合群` |
| `__BADGE__` | 封面角标 | `{省份} · 医患共建 · 公益` |
| `__HEADLINE__` | 主标题 | `{医院}{科室} × 小胰宝社区<br>共建{省份}病友联合群` |
| `__SUBTITLE__` | 封面副信息 | `{科室} ｜ {主任}团队提供医学支持 ｜ 小胰宝志愿者提供社区服务` |
| `__INTRO__` | 导语 3 段 | 痛点 → 这个群做什么（三件事）→ 本文说清什么 |
| `__DISEASE_SCOPE__` | 病种范围（完整说法） | 如「消化系统肿瘤——胰腺癌、胆道癌、胃癌、结直肠癌、肝癌」 |
| `__DISEASE_SCOPE_SHORT__` | 病种范围（短语） | 如「消化系统肿瘤」 |
| `__INDEX_CANCER__` | 举例用的癌种 | 挑一个有代表性的，如「胰腺癌」 |
| `__CYCLE_DAYS__` | 化疗周期描述 | 如「2–4 周」，须有指南依据 |
| `__COMMON_COMPLICATIONS__` | 常见并发症列举 | 如「黄疸、腹水、疼痛、营养」 |
| `__HOSPITAL_POSITION__` | 医院定位收尾段 | **必须核医院官网**；与 `__HOSPITAL_INTRO__` 同源资料，不要写「本地不输外地」这类比较句 |
| `__HOSPITAL_INTRO__` | 医院介绍段 | 定位 / 级别 / 区域医疗中心 / 托管共建 / 重点中心 |
| `__DEPT_PROFILE_TITLE__` | 科室概况小标题 | `{科室} · 科室概况（据医院官网公开信息）` |
| `__DEPT_PROFILE__` | 科室概况条目 | 用 `· ` 悬挂条目；规模 / 诊疗范围 / 治疗手段 / 介入支持 / 特色技术 |
| `__DEPT_FEATURE__` | 科室亚专业与门诊段 | 亚专业方向 + MDT 排班（注明「以医院当日公示为准」） |
| `__DEPT_STRATEGY__` | 学科战略定位块（**可选**） | 定位原文 + 患者解读；**没有公开资料就整块删除**，禁止硬编；结构见下方第 4 条 |
| `__COMPLICATION_LIST__` | 并发症列举（正文句式） | 如「胆道梗阻、消化道出血、腹水、疼痛、营养状况下滑、血栓风险」 |
| `__COMPLICATION_COOP__` | 协作机制段 | 主任牵头的跨科室协作 + 「让患者院内一次解决」的落点 |
| `__DIRECTOR__` | 主任介绍整块 | 结构见下方第 4 条 |
| `__TRIALS__` | 临床招募整块 | 结构见下方第 5 条 |
| `__PROVINCE__` | 省份 | 用于志愿者招募节 |
| `__GEO_SCOPE__` | 覆盖地域 | 如「山西及周边地区」 |
| `__QR_LABEL__` | 二维码卡片标题 | 如「{医院}{科室} · 合作群」 |
| `__QR_URL__` | 二维码图片地址 | **路径只能含 `[A-Za-z0-9/._-]`**，见下方第 6 条 |
| `__QR_ALT__` | 二维码 alt | 如「{医院}{科室}合作群二维码」 |
| `__FOOT__` | foot 固定区域 | 直接粘贴 `review_foot_purple.html` 全文，**逐字照抄** |
| —（非占位符） | 资料来源行 | 模版里**没有**对应的 SOURCES 占位符（源文件注释中仅作提示），写法见下方第 7 条 |

## 3. 写死的内容（勿改）

以下四块是固定话术，**换医院也不要改**（只在需要时替换省份名）：

1. 品牌头部（渐变条 + logo + 「AI+人文 · 全心全意为患者」）
2. **⚠️ 三条边界**——公益性质 / 群内经验不能照搬 / 信息以官方公示为准
3. **06 社区提供什么**——AI 工具矩阵 + 蓝马甲志愿者（工具名如变化需同步）
4. **07 志愿者招募**的主体措辞 + **结尾寄语**（「家门口的好医生，值得被看见」）

## 4. `__DEPT_STRATEGY__` 的标准结构（可选，用于把「科室能力」写厚）

医院想让患者知道的不只是「有什么设备」，还有「往哪走」。科室通常有现成的学科战略/定位资料（汇报 PPT、
学科介绍、区域医疗中心建设材料），**提炼成「定位原文 + 患者解读」两层**即可，不要整段搬。

```
14px 引导段：这些是科室现在的能力。它接下来往哪走，可以从公开的学科战略定位里看——N 条主线：
└─ 浅紫底卡片（background:#f2eff7; border:1px solid #e3dcf0）
   ├─ 13px 主色小标题：科室公开的学科战略定位
   ├─ 12px 灰字说明：定位放在 N 条主线上 + 资料中标注的参照文件 + 「加粗为定位原文，下面一句是它落到患者身上的意思。」
   └─ 每条一个白底子卡（background:#fff; border-radius:8px）
       ├─ `<span style="color:#9b8bb8;">01</span>　{定位原文}`（13px 加粗）
       └─ {患者视角解读}（13px 正文，一句话）
└─ 收尾段：N 条主线读下来，指向的是同一件事：<strong>把省内能做的事做扎实，让患者不必为了一个常规环节反复奔波。</strong>
```

硬规则：

- **定位原文逐字照抄**（如「区域疑难危重症肿瘤诊疗高地」「强化放疗优势，建设综合诊疗示范中心」），
  不改写、不加形容词、不合并条目。
- **「建设」＝目标，不是成就**。定位里写「建设…示范单位 / 引领平台」的，解读句必须用
  「方向是 / 目标是 / 争取」，**禁止**写成「已经是 / 已建成 / 已获批」。
- **患者解读要落到具体动作**（省内能接住 / 同一体系内协同 / 多一条合规可及路径 / 持续向基层下沉），
  不要写成「提升服务水平」这类空话。
- 解读句可以引用后文节号（如「后文 05 节具体说」），但**不要提前点名还没出场的医生**——
  主任在第 04 节才介绍，前面直呼姓名会造成「谁？」的断裂感。
- 资料里标注的**参照文件要连书名与年份一起写**（如《综合性医院肿瘤中心建设中国专家共识》2024 版），
  并同步加进 foot 的「资料来源」行。
- 板块位置：接在 `__DEPT_FEATURE__` 之后、第 02 节收尾。它的四条主线天然对应后文——
  01/02 → 第 03 节并发症与协作，03 → 第 05 节临床招募，04 → 第 04 节主任的资源下沉。
- 科室**没有**公开战略资料时，整块删除；宁可少一节，不要自己替医院编定位。

## 5. `__DIRECTOR__` 的标准结构

```
小标题：04　这位医生是谁（+ 1 段引导）
└─ 浅紫底卡片（background:#f2eff7; border-left:3px solid #5c4a7a）
   ├─ 姓名（14px 加粗）
   ├─ 身份行（13px 主色）：学历 ｜ 职称 ｜ 导师类型 + 医院科室职务（两行）
   ├─ 教育与进修经历（12px 灰小标题 + 13px 正文）
   ├─ 专业擅长
   ├─ 学术任职（部分）——只列公开可查的
   └─ 把资源往下沉（博士工作站 / 下沉活动，有则写）
```

**头衔必须核医院官网**。第三方平台更新滞后（2026-10 实测：官网已是「主任医师、博士研究生导师、肿瘤中心副主任」，好大夫仍写「副主任医师、硕士生导师」）。**取最新官网口径**；官网没写的兼任职务不写。

## 6. `__TRIALS__` 的标准结构

```
16px 主色加粗小节标题：05　临床研究招募：直连，不经过中介
├─ GCP 资质段（是否 GCP 参与科室 / 承担项目量级 / 重点方向）
├─ 主任承接的研究清单（浅紫底卡片 + `· ` 悬挂条目）
│   每条格式：病症 → 药物/方案 → 分期（编号）
└─ 13px 灰字免责：仅为公开信息中的部分研究；入排严格、状态变化；
   是否适合由研究医生按方案评估；群内同步信息但不承诺入组
```

**必须区分「作为 PI 承接」与「参与」**。研究编号（GCP-xxxx-xxx / NCT / CTR）有则写，没有不编。

## 7. 二维码

- **必须独占一行**（`skill.md` §5.3 规则 5）。两张码并排时，窄屏下码会小于 140px 下限，数学上放不下。
- 上图为真码、下图为占位框时，两者各自独占一行。
- **没有第二个群就不要留空占位框**——空占位看起来像未完成。
- 图片地址路径**只能含 `[A-Za-z0-9/._-]`**。含 `%`、括号、空格、中文会被微信编辑器二次编码成 404，表现为「复制到编辑器图片不显示」。上传用 `picgo-cos-upload` 技能。
- 生成后必跑 §5.3 验扫（1x 渲染截图 → Vision 解码），确认页面上缩小后仍扫得出来。

## 8. 来源行

写在 foot 免责声明块内（母版原句之后，另起 `<p>`，**不要塞进母版已有的段里**）：

```
<p style="margin:5px 0 0;">文中科室与服务信息来自公开渠道，实际情况请以医院与社区最新公示为准。</p>
<p style="margin:0;">资料来源：{医院}官网（{科室}科室介绍与医生团队公开信息）；微信百科「{主任}」词条；{医院}国家区域医疗中心建设相关公开资料。</p>
```

> 母版固定的「本文仅供科普参考，不构成医疗建议或投资建议。」**必须单独成段**。在它后面追加文字会让 foot 逐字比对失败（报「缺 N 段」）。
